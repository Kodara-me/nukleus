# Nukleus 0.4.0

*A web interface* · 2026-10-26

Nukleus is a local backend for AI applications on Linux. It runs as a systemd service,
owns the installed models and executes image and text jobs in one FIFO queue, so several
client applications share the same models and GPU over a WebSocket protocol. This release
adds a second service to the suite, `nukleus-web`, and makes the installer opt-in per
component.

## Highlights

- **`nukleus-web`**: a basic responsive web interface (phone, tablet and PC) over
  Nukleus's models. It has no AI features of its own and is meant for the local network
  only. It is a minimal HTTP/1.1 server on `QTcpServer` with access checks (source
  address, `Host` and `Origin` checks, request limits). There is no sign-in in this
  version. It listens on `127.0.0.1` and on one configured LAN IPv4 address, port 9385,
  and reaches `nukleusd` through the SDK, with a token only for a non-loopback backend.
- **Four actions**: Text to image, Image to image, Edit (a source image plus up to 7
  references) and Image to video (start and end images, MP4 when the capability exists).
  Models are listed per action.
- **Uploads and jobs**: images are PNG or JPEG, up to 32 MiB per image and 96 MiB per job,
  decoded and scaled to the model's budget. The service keeps a local queue of 8 jobs,
  sent to the backend one upload at a time, and the 20 most recent results in memory. A
  job is reachable only by its random identifier.
- **Installer**: one opt-in flag per component, `--install-backend` and
  `--install-web-service` (with `--web-binary`, `--web-listen`, `--web-backend-host` and
  `--web-backend-token`). With no flag, the installer only updates what is already
  installed, and a fresh host stops with an error naming both flags. A first installation
  of the backend therefore now needs `--install-backend`; the README and the
  `get-nukleus.sh` one-liner say so. `get-nukleus.sh` stops before any download when
  nothing is installed and no component flag is given. It creates the `nukleus-web`
  account and `/etc/nukleus/web-backend-token`. The uninstaller removes the web service
  (with `--purge`, its configuration and token file) and deletes no account.
- **SDK**: `ServiceClient::submitEdit` now sends `seed`.
- **Documentation**: the README opening is rewritten for any client application, the
  reference material moved into `docs/`, and the install script stops early on a storage
  tree whose group has no name.

Existing features from 0.3.0 are unchanged: image, text and animation jobs, the model
catalogue, presets, the Manager, the SDK and the systemd deployment of `nukleusd`.

The protocol stays v3: the SDK change is additive, and clients built with the 0.3.0 SDK
keep working.

## Requirements

Linux with systemd, CMake 3.24+, a C++20 compiler, Qt 6.5+ (Network, WebSockets, Widgets,
SVG, LinguistTools) and LibArchive. [Ardoise](https://github.com/jstmichel/ardoise) 0.1 is
used when installed, otherwise cloned by CMake. Image and text jobs need `sd-cli` and
llama.cpp (`llama-server`, `llama-completion`) on the service's `PATH`. Ping-pong loops and
MP4 output need `ffmpeg` with libx264 (MP4), libvpx (WebM loops) and libwebp (WebP loops).
`nukleus-web` needs a reachable `nukleusd`, on the same host or another one.

## Notes

Automated tests cover the web service, the installer and the SDK, and run on Arch Linux in
CI. Some limits are not validated or not handled yet:

- The status page and the forms have not been checked on a real phone browser yet; a manual
  check is pending.
- The real `nukleusd` answers `authentication-failed` for a protocol-version mismatch, so
  the page shows "authentication refused" in that case.
- EXIF orientation is not applied to uploaded photos, so a photo taken in portrait may
  appear rotated.
- There is no sign-in: access relies on the local-network checks only, so expose the
  service on a trusted network.
