# Nukleus 0.5.0

*Windows services* · 2026-10-30

Nukleus is a local backend for AI applications. It owns the installed models and executes
image and text jobs in one FIFO queue, so several client applications share the same
models and GPU over a WebSocket protocol. This release brings the suite to Windows 11: the
daemon and the web service run as Windows services, started with the machine, and a
PowerShell installer sets them up.

## Highlights

- **Windows build**: `nukleusd`, `nukleus-web` and `nukleus-manager` build and run with
  MSVC 2022 and Qt 6.8, with LibArchive from vcpkg. The tests that need a POSIX shell or
  POSIX permissions are skipped on Windows with their reason.
- **Windows services**: `nukleusd` and `nukleus-web` run under the Service Control Manager
  as `nukleus` and `nukleus-web`, each under its own virtual account. They report Start
  Pending, Running and Stopped, stop in under a second on a Stop request, and exit with a
  service-specific code when they fail to start (1 for a busy port, 2 for bad options).
  `NUKLEUS_LOG_FILE` makes both programs write their messages to a file with a 10 MiB
  rotation, on every platform.
- **PowerShell installer**: `scripts/install-nukleus.ps1` installs, updates and removes the
  services (`uninstall-nukleus.ps1`), with one opt-in flag per component
  (`-InstallBackend`, `-InstallWebService`), a `-DryRun` plan, and a Start menu entry for
  the manager. An update keeps the existing options, tool paths and storage. Relative path
  options resolve against the PowerShell location.
- **Permissions**: the installer secures the configuration, logs and token files for the
  service accounts, extends (never replaces) the permissions of the weight directory, and
  refuses a tool path under a user profile. It now also checks that the daemon account can
  run each runtime tool (`llama-server`, `llama-completion`, `sd-cli`, `ffmpeg`) and, when
  it cannot, as with a WinGet package whose files carry their own permissions, grants it
  read and execute on that tool's folder.

## Requirements

Windows 11 with the runtime tools installed machine-wide: `sd-cli` (Vulkan build),
llama.cpp (`winget install ggml.llamacpp --scope machine`) and ffmpeg. Linux installation
is unchanged.

## Known issues

- A weight directory at the root of a drive breaks the service registration (`sc.exe`
  exit code 1639); use a subfolder (#47).
- The manager shows no icon in the Start menu or the taskbar (#48).
- The installer deploys the Debug Qt libraries when built from a Debug tree; build in
  Release for a lighter install.
- The installer test case "a non-elevated install says why" fails on the Windows machine
  used for this release; it is not related to the service work.
