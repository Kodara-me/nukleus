# Nukleus 0.3.0

*Image animation* · 2026-10-24

Nukleus is a local backend for AI applications on Linux. It runs as a systemd service,
owns the installed models and executes image and text jobs in one FIFO queue, so several
client applications share the same models and GPU over a WebSocket protocol.

## Highlights

- **`image.animate`**: a new operation that animates a start image, with an optional end
  image, into a video through `sd-cli` and an installed animation model such as Wan 2.2.
  Every `sd-cli` video option that does not point to a file or a network address can be
  sent (67 options in the shared option table), validated before the upload and checked
  against the installed `sd-cli`'s `--help` for names such as samplers and schedulers. Each
  option takes the request's value, then the model's default, and is left out when neither
  is set, so `sd-cli`'s own default applies. LoRA tags are added per stage with the weights
  of the request or the model, and a weight of 0 leaves a LoRA out. Progress uses `sd-cli`'s
  steps like image jobs, counts the high-noise and low-noise passes as one run, and never
  goes back. Disconnecting cancels the job.
- **Ping-pong loops**: the `pingPong` option makes Nukleus play the video forward then
  backward (2N - 2 frames) after generation, with ffmpeg. It works in every container and
  can be a model default.
- **MP4 output**: `container: "mp4"` returns H.264 video (yuv420p, fast start, `video/mp4`)
  encoded from `sd-cli`'s output with ffmpeg in the same pass as ping-pong. WebM, animated
  WebP and AVI remain available as `sd-cli` writes them.
- **Container check**: the file `sd-cli` writes is checked against the container that was
  asked for. A build of `sd-cli` without libwebm writes AVI under a `.webm` name; that now
  fails with `generation-failed` and names both containers instead of returning mislabelled
  video.
- **Quality**: `compressionQuality` also sets the quality of every ffmpeg encode (WebP, MJPEG,
  H.264, VP9). Without it, the ffmpeg encoders use the equivalent of quality 90.
- **Optional ffmpeg**: ffmpeg is found on the `PATH` or through `NUKLEUS_FFMPEG`, like
  `llama-server`. The service lists `image.animate.pingPong` and `image.animate.mp4` among
  its capabilities only when ffmpeg runs, and a request that needs it without ffmpeg fails
  with `backend-not-ready` before any upload.
- **SDK**: `canAnimate()`, `canPingPong()`, `canAnimateMp4()`, `submitAnimation()` and
  `animationFinished()`, with the matching `ServiceCapabilities` fields and the option
  table in `Nukleus::Protocol`.
- **Manager**: the model panel of an animation model has one field per video option, in
  groups (Video, Sampling, LoRA, Cache, Memory and VAE tiling) with each high-noise option
  next to its low-noise counterpart. An empty field means no default, an invalid value
  blocks Save with a message, and defaults set through the API are kept across a save.

Existing features from 0.2.0 are unchanged: image jobs, text jobs, animation models and their
files, the model catalogue, presets and editing qualities, the SDK and the systemd
deployment.

The protocol stays v3: the changes are additive, and clients built with the 0.2.0 SDK keep
working but do not see the new operation until rebuilt.

## Requirements

Linux with systemd, CMake 3.24+, a C++20 compiler, Qt 6.5+ (Network, WebSockets, Widgets,
SVG, LinguistTools) and LibArchive. [Ardoise](https://github.com/jstmichel/ardoise) 0.1 is
used when installed, otherwise cloned by CMake. Image and text jobs need `sd-cli` and
llama.cpp (`llama-server`, `llama-completion`) on the service's `PATH`. Ping-pong loops and
MP4 output need `ffmpeg` with libx264 (MP4), libvpx (WebM loops) and libwebp (WebP loops);
without it, the service starts as before and does not offer them.

## Notes

Automated tests use fake runtime tools, including a fake ffmpeg, and run on Arch Linux in
CI. Real image and text jobs have been exercised with Vulkan builds on an AMD Radeon GPU;
other GPUs and backends are not yet validated. The service lists `image.animate.mp4` when
ffmpeg answers `-version`, without checking its encoders yet, so an ffmpeg built without
libx264 would advertise MP4 and then fail the job.
