# Nukleus 0.6.0

*Guided generation and LoRA training* · 2026-11-10

Nukleus is a local backend for AI applications. It owns the installed models and executes
image and text jobs in one FIFO queue, so several client applications share the same
models and GPU over a WebSocket protocol. This release gives `image.generate` more ways to
steer an image (a mask, a ControlNet and LoRAs) and lets clients train their own LoRAs
from a set of images.

## Highlights

- **Masked generation**: with `hasMask`, `image.generate` takes a mask after the source
  image (white redraws, black keeps). The service checks that the mask is a PNG or JPEG of
  the source's size and passes it to `sd-cli` with `--mask`. It advertises
  `image.generate.mask`. The SDK adds `ImageGenerationRequest::maskImageData` and
  `ServiceClient::canGenerateWithMask()`.
- **ControlNet**: a new `controlnet` companion subtype, and `controlNetModelId`,
  `controlStrength` and a control image on `image.generate`. The service advertises
  `image.generate.control`.
- **LoRAs in generation**: a new `lora` companion subtype (safetensors or GGUF), and a
  `loras` option on `image.generate` with 1 to 8 installed LoRAs and their weights (-10 to
  10, default 1). LoRA tags written directly in prompts are rejected, and so is deleting a
  LoRA that a job uses. The service advertises `image.generate.lora`. The SDK adds
  `LoraWeight`, `ImageGenerationRequest::loras` and `ServiceClient::canGenerateWithLoras()`.
- **LoRA training**: the new `lora.train` operation trains a LoRA with kohya-ss/sd-scripts
  (named by `NUKLEUS_LORA_TRAINER`) from uploaded images and captions. It reports its
  progress, stops the trainer's whole process tree when the job ends, and installs the
  result as a `lora` companion under its exact name. The SDK adds `LoraTrainingRequest`,
  `ServiceClient::canTrainLoras()`, `submitLoraTraining()` and the `loraTrainingFinished`
  signal. `docs/lora-training.md` covers the setup.
- **Windows installer**: `install-nukleus.ps1 -LoraTrainer DIR` stores the trainer and
  keeps it on later runs. It refuses a trainer, or a venv home, under `C:\Users`, and
  grants the service account access only when that account cannot run the venv's Python.

## Fixes

- On Linux, a process group that only holds zombies now counts as ended. Before, a job
  could stay running forever in a container whose PID 1 never reaps.

## Requirements

LoRA training needs kohya-ss/sd-scripts, pinned at `cb70b96`, with its venv. The Windows
setup is verified. The Linux setup is documented but not yet verified.

## Known issues

- A weight directory at the root of a drive breaks the service registration (`sc.exe`
  exit code 1639); use a subfolder (#47).
- The manager shows no icon in the Start menu or the taskbar (#48).
- `lora.train` cannot be cancelled. A client that disconnects stops its training.
