# Nukleus 0.1.0

*First release* · 2026-10-19

Nukleus is a local backend for AI applications on Linux. It runs as a systemd service,
owns the installed models and executes image and text jobs in one FIFO queue, so several
client applications share the same models and GPU over a WebSocket protocol.

## Highlights

- **Image jobs**: `image.generate` and reference-image `image.edit` through
  [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp)'s `sd-cli`, with
  step-by-step progress, shared VAE and LLM text encoders, and detailed failure diagnostics.
- **Text jobs**: multi-turn `text.chat` with optional image inputs, JSON-schema replies and
  explicit load/unload, plus `prompt.enhance`, on a managed loopback `llama-server` from
  [llama.cpp](https://github.com/ggml-org/llama.cpp).
- **Model catalogue**: image-generation, upscaler, LLM and companion (VAE, MMPROJ) models
  installed from HTTPS or local files, never overwriting weights, with recommended options,
  display names, explicit-content classification and default LLM roles.
- **Presets and editing qualities**: service-owned routing that clients resolve by preset or
  quality, with prompt prefixes and Steps/CFG snapshots.
- **Manager**: `nukleus-manager` GUI and `list`/`add`/`attach`/`delete` CLI, connecting
  locally or to an authenticated LAN service.
- **SDK**: the `NukleusSdk` CMake package (`Nukleus::Protocol`, `Nukleus::SDK`) with a Qt
  client, protocol types and `.kiraid` identity packages.
- **Deployment**: a systemd installer with loopback or LAN listening, a shared token, an
  optional split storage layout for shared weight trees, a remote updater, and
  `get-nukleus.sh` to build, test and install a release with one command.

## Upgrading from Kira Service

Nukleus was previously named Kira Service. The installer migrates an existing deployment in
place: account and group are renamed with their IDs, `/etc/kira-service` and
`/var/lib/kira-service` move to their `nukleus` names, `KIRA_SERVICE_*` settings become
`NUKLEUS_*`, and the former manager files are removed. The protocol (v3) and port `9384` are
unchanged. SDK consumers switch to `NukleusSdk`, `Nukleus::SDK` and `<nukleus/…>` headers.

## Requirements

Linux with systemd, CMake 3.24+, a C++20 compiler, Qt 6.5+ (Network, WebSockets, Widgets,
SVG, LinguistTools) and LibArchive. [Ardoise](https://github.com/jstmichel/ardoise) 0.1 is
used when installed, otherwise cloned by CMake. Image and text jobs need `sd-cli` and
llama.cpp (`llama-server`, `llama-completion`) on the service's `PATH`.

## Notes

Automated tests use fake runtime tools and run on Arch Linux in CI. Real image and text jobs
have been exercised with Vulkan builds on an AMD Radeon GPU; other GPUs and backends are not
yet validated.
