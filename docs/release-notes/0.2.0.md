# Nukleus 0.2.0

*Animation models* · 2026-10-24

Nukleus is a local backend for AI applications on Linux. It runs as a systemd service,
owns the installed models and executes image and text jobs in one FIFO queue, so several
client applications share the same models and GPU over a WebSocket protocol.

## Highlights

- **Animation models**: a new `animation` model category in the service for image-to-video
  models such as Wan 2.2. An animation model has a primary low-noise diffusion model, an
  optional high-noise model and optional low-noise and high-noise LoRAs, plus shared VAE
  and `t5xxl` text-encoder companions. Companions gain the `t5xxl` subtype, assigned
  companions cannot be deleted or retyped, and deleting an animation model keeps them.
  Model listings report `missingFiles` for absent files or companions instead of hiding the
  model, and the SDK exposes the category and `missingFiles`.
- **Manager support**: `nukleus-manager` shows an animation branch in the model tree, and
  the Companion branch gains a T5-XXL group. The add form installs the companions first and
  an optional files dialog completes an existing model. The CLI gains `--high-noise`,
  `--lora-low-noise`, `--lora-high-noise`, `--vae-model` and `--text-encoder-model` for
  `add` and `attach`, `--companion-type` accepts `t5xxl`, and `list` shows animation models
  with their missing roles.

Existing features from 0.1.0 are unchanged: image jobs, text jobs, the model catalogue,
presets and editing qualities, the manager, the SDK and the systemd deployment.

The protocol stays v3: the changes are additive, and clients built with the 0.1.0 SDK see
animation models as an unknown category until rebuilt.

## Not in this release

`image.animate` (specified in nukleus#3) is not part of 0.2.0. Animation models can be
installed, completed and kept, but jobs cannot run them yet.

## Requirements

Linux with systemd, CMake 3.24+, a C++20 compiler, Qt 6.5+ (Network, WebSockets, Widgets,
SVG, LinguistTools) and LibArchive. [Ardoise](https://github.com/jstmichel/ardoise) 0.1 is
used when installed, otherwise cloned by CMake. Image and text jobs need `sd-cli` and
llama.cpp (`llama-server`, `llama-completion`) on the service's `PATH`.

## Notes

Automated tests use fake runtime tools and run on Arch Linux in CI. Real image and text jobs
have been exercised with Vulkan builds on an AMD Radeon GPU; other GPUs and backends are not
yet validated.
